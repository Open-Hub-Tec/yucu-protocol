# Plan de informes — Equipo 8

**Módulo:** #121 — La pantalla de entrevistas ya no guarda nombres ni teléfonos de compradores  
**Organización:** Red de vendedores-tejedores de textiles de telar de cintura de Santo Tomás Ocotepec, Tlaxiaco, Oaxaca

## 1. Destinatarios

- **Organización (red de vendedores-tejedores de Santo Tomás Ocotepec):** recibe información sencilla sobre los avances, las pruebas en su comunidad y lo que se necesita de ella.
- **Product Owner (docente / propietario del producto):** revisa los entregables y toma decisiones sobre los requisitos y las fechas.
- **Equipo de desarrollo (Equipo 8):** consulta tareas, responsables, fechas y bloqueos.
- **Financiador:** no aplica; el módulo no tiene financiamiento externo. Si llegara a participar uno, recibiría información general sobre avances y uso de recursos.

## 2. Matriz de comunicación

| Información | Destinatario | Frecuencia | Medio | Responsable |
|---|---|---|---|---|
| Avances del proyecto | Organización | Semanal | Informe breve impreso o nota de voz | eduScrum Master del equipo (@Angeeell-01) |
| Estado de tareas | Equipo | Durante el sprint | GitHub Projects | Responsable de seguimiento |
| Entregables | Product Owner (docente) | Por entrega | Pull Request | Integrante responsable de la entrega |
| Acuerdos | Organización y equipo | Después de cada reunión | Minuta | Secretario de la reunión |
| Problemas importantes | Product Owner (docente) | Cuando ocurran | Comentario en GitHub | Responsable de seguimiento |

Las evidencias se conservarán mediante informes, minutas y registros de GitHub, sin incluir datos personales de compradores ni de personas de la comunidad.

## 3. Formato del informe

Cada informe tendrá una extensión aproximada de una página e incluirá:

- Periodo informado.
- Avances respecto a lo planeado.
- Actividades completadas.
- Actividades pendientes.
- Problemas o bloqueos.
- Decisiones que se necesitan.
- Próximos pasos y fechas.

Se utilizará lenguaje sencillo para facilitar su comprensión por parte de la organización.

## 4. Indicadores de progreso

Se utilizarán los siguientes indicadores:

| Indicador | Forma de medición | Fuente |
|---|---|---|
| Entregables completados | Completados frente a planeados | GitHub Projects |
| Horas de trabajo | Horas reales frente a estimadas | Registro del equipo |
| Costos | Horas registradas por tarifa acordada | Hoja de cálculo |
| Avance acumulado | Gráfica burn-up de entregables terminados | GitHub Projects (Insights) |
| Actividades pendientes | Tareas abiertas | Issues y GitHub Projects |
| Calidad | Revisiones y pruebas aprobadas | GitHub Actions |

Los valores se actualizarán con los datos reales disponibles. No se asignarán cifras sin evidencia.

## 5. Semáforo y escalada

| Estado | Condición | Acción |
|---|---|---|
| Verde | Actividades conforme al calendario | Continuar con el plan |
| Ámbar | Retraso de hasta dos días | Revisar causas y ajustar actividades |
| Rojo | Retraso mayor a dos días o bloqueo importante | Informar al Product Owner y proponer soluciones |

Los retrasos que afecten una fecha comprometida se comunicarán a la organización con al menos un día de anticipación, siempre que sea posible.

## 6. Herramientas

| Herramienta | Uso | Justificación |
|---|---|---|
| GitHub Projects | Seguimiento de tareas | Permite organizar actividades y avances |
| Issues y Pull Requests | Control de entregas | Facilitan la revisión y documentación |
| GitHub Insights | Consulta de actividad y burn-up | Permite revisar el avance sin trabajo extra |
| Hoja de cálculo | Registro de horas y costos | Facilita los cálculos |
| Nota de voz | Comunicación con la organización | Útil cuando se requiere una explicación sencilla y hay poca señal |
| Hoja impresa | Consulta sin conexión | Permite revisar información cuando no hay internet |

Las notas de voz se entregarán directamente a la organización. En el repositorio únicamente se conservará su texto, sin información personal ni grabaciones.

## 7. Adaptación a la comunidad

Los informes dirigidos a la organización utilizarán lenguaje claro, evitando términos técnicos innecesarios. Se entregarán impresos o mediante el medio acordado, considerando que en Santo Tomás Ocotepec la señal puede ser limitada (sin conexión estable) y respetando los tiempos de la comunidad.

## 8. Actas y acuerdos

Cada reunión tendrá una minuta que registre los temas tratados, acuerdos, responsables por rol, fechas de cumplimiento y aprobación.

Los acuerdos se convertirán en tareas dentro de GitHub Projects para facilitar su seguimiento.
